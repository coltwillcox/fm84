# 📖 FM84 - Usage

Everything fm84 does, in full. The [README](../README.md) has the short version, [KEYS.md](KEYS.md) every key, and `man ./doc/fm84.1` the manual page.

## 🗂️ Navigation
- 📁 **Dual-pane layout** - because one panel is never enough
- ⌨️ **Arrow keys** - glide through your files
- 🏠 **Home/End** - teleport to the edges
- 📄 **PageUp/PageDown** - cruise in style
- 🔀 **Tab** - switch between panels like flipping cassettes
- ↔️ **Ctrl+← / Ctrl+→** - send the left or right panel to the directory under the cursor, keeping the focus where it is; on a file, to the directory it is in
- 🔁 **Ctrl+U** - swap the panels, as in Midnight Commander: each takes its tabs, cursor, selection and history to the other side, and the focus goes with the one it was in. Its filter, git marks and watcher go with it, so neither is read again
- 🪞 **Alt+I** - send the other panel to this one's directory, its cursor on the same entry
- ↩️ **Enter** - dive into directories, and into archives - see [Archives](#-archives)
- 🚀 **Shift+Enter** / **Ctrl+O** - open what is under the cursor as the system would, with the program it opens that kind of file with - or the one you set for its extension, as below; an archive too. Ctrl+O is for terminals that send Shift+Enter as plain Enter - GNOME Terminal, Konsole, xterm, Terminal.app, tmux - where only kitty's keyboard protocol (kitty, foot, WezTerm, Ghostty, Alacritty) or Windows tells them apart
- 🧰 **Alt+O open with** - the programs the entry under the cursor can be opened with, to pick one: your own for its extension first, then on Linux and the BSDs the applications the desktop says take its type - read from the same files `xdg-open` and the file managers read, a Rust source finding every editor that takes plain text - then the system's default, and on Windows its own Open With dialog. **Enter** or **1**…**9** opens it, **E** edits your list, **Esc** closes. One marked `[terminal]` runs in this terminal, fm84 coming back when it is done; the rest open in windows of their own. Inside an archive the file is copied out first
- 🗂️ **Your own programs, by extension** - kept in `open` beside the config, a line each as `pdf epub = zathura`: extensions without their dots, any case, `tar.gz` too, `*` for every file. The first line that fits is what **Enter** and **Shift+Enter** open a file with, in place of the system's choice. The command runs in the shell, in the file's directory, with `{file}` where the file goes - on the end when it is not there - `{dir}` its directory, and `{name}` and `{other}` as in the user menu. A `!` in front runs it in this terminal, as `md = !vim`, waiting for Enter only when it fails. Alt+O's **E** makes the file, with examples
- ⬅️ **Backspace** - ascend to parent realm
- 🧭 **Ctrl+L** - or a click on a panel's path - edit the active panel's path in place, in the line above it, and go there with **Enter** (**Esc**, or a click anywhere else, leaves it as it was). **Tab** fills out a name as far as the entries agree, `~` is home, and a path without a leading `/` starts from the panel. A file is landed on, in the directory it is in; somewhere that is not there is said to be, and the panel stays put
- ⏪ **Alt+← / Alt+→** - back and forward through where the tab has been, as in a browser, landing on the entry the cursor was on. Each tab keeps its own, up to 50 steps back; a directory gone since is passed over
- 🕰️ **Alt+↓ directory history** - every directory either panel has been in this run, across all their tabs, newest first and each once, opening on the newest that is not where you are - so Alt+↓ then Enter goes back to where you just were. Typing narrows it to the paths that hold every word typed, in any order (`mus k` finds `~/music/rock`), lower case matching either case; **↑/↓** and **PgUp/PgDn** choose, **Enter** goes, **Esc** closes. One gone since is said to be, and the panel stays put
- 🔖 **Bookmarks** - **Ctrl+D** lists the directories kept to go back to: **Enter**, or **1**…**9**, takes the panel there, **A** or **Insert** keeps the panel's directory, **D** or **Delete** forgets the one highlighted, **Shift+↑/↓** move it up or down the list. The panel's own directory is marked. One that has gone since is said to be, and the panel stays put. Kept in `bookmarks` beside the config, a `bookmark = path` line each, fine to edit by hand
- 🔗 **Symlinked directories** - listed and entered like the real thing
- 🔒 **Directories you cannot read** - refused with the reason, and the panel stays where it was
- 🌿 **Git branch** - after a panel's path, the branch its directory is on when it is in a repository, or the commit when none is checked out. Read from the repository's own files, worktrees and submodules too, on the thread that reads the directory - no git needed, and no wait. It is the first to give way when the path needs the room
- 🔀 **Switch branches** - click the branch and a popup lists the repository's local branches, the one checked out marked `•`. Pick one with the arrows and Enter, or click it and click it again; both panels are read again, so the label and the files follow. When git refuses - edits that the switch would lose - its own reason is shown and the branch stays as it was. This part runs git itself, so it needs git 2.23 or newer
- 🏷️ **Git marks** - at the end of each name, what git says of it: **M** modified, **S** staged, **?** untracked, **!** ignored, **U** in conflict. A directory shows the strongest of what is changed inside it, and inside an untracked or ignored one everything is marked as it is. Asked of git on a thread of its own once the listing is in, so a large repository never holds the panel up - one at a time for each panel, however often it is reread - and matched whichever way an accent is written. Under Ctrl+B each file has its own. F11 turns them off
- 🧑‍🔧 **Git from the panel** - **Alt+G** on what is chosen - the selection, or the entry under the cursor: **S** stages it, new files too, **U** takes it back out of the index, leaving the file as it is (before the first commit too), **D** throws away its changes that are not staged, after asking, and **C** shows the file side by side with HEAD's, in the Compare view. Each is asked of the repository it is in, so it works in a fed panel too; git's own words say why when it will not. The marks follow at once
- 🕰️ **Any commit as a folder** - **R** on Alt+G lists what there is to open: the local branches, the one checked out marked `•`, then the remotes', the tags newest first, the stashes and the last 50 commits, each with how long ago and its subject. Typing narrows them by the words in a name or a subject; **Enter** opens the one chosen, or - with nothing listed - what was typed, as `HEAD~3` or a hash. It opens as a read-only folder in the active panel at the directory the panel was in, as an archive is gone into, its path `<top of the repository>/@git:<revision>`: F3 views a file as it was, F5 copies it out, Shift+F3 compares it with today's in the other panel, and nothing writes into it. Every entry is dated as the commit; links come out as links, and submodules are listed but cannot be read
- 👤 **user@host** - who fm84 runs as and where, beside the logo, reversed when it is root. Left off on a terminal too narrow for it
- 💿 **Drive switcher** - click a drive icon, or use Alt+F1 / Alt+F2 (or Ctrl+F1 / Ctrl+F2), to send either panel to a mount; the one each panel is on sits in a block of colour, and removable and optical media get their own icons, including a USB stick mounted under `/run/media`. With more drives than fit, the strip shows a window onto them: `<` and `>` at its ends, or the wheel over it, move it a page along, and it follows the panel's drive and the one being chosen
- 📑 **Tabs** - each panel keeps its own, in the row under its drives. **Ctrl+T** opens one beside the current tab in the same directory, **Ctrl+W** closes it (a panel keeps its last), **Ctrl+PgUp** / **Ctrl+PgDn** go round them and **Alt+1**…**Alt+8** to that tab, **Alt+9** to the last. Click a tab to show it, middle-click to close it. Each remembers its directory, cursor and selection, and with Remember directories on (F11) they are all there next time

## 🔍 Quick Search
- 🔎 **Type-ahead search** - just start typing to find files
- ⬆️⬇️ **Navigate matches** - Up/Down arrows jump between results
- 🧹 **Esc** - clear the search vibes
- 🧪 **Ctrl+S filter** - narrows the panel to what a pattern matches, as it is typed, for a directory of thousands where search only moves the cursor. A word on its own is looked for anywhere in the name (`rep` finds `report.txt` and `prep/`); `*`, `?` and `[a-z]` work as for `+`, several separated by `;`, and one ending in `/` keeps only directories. Lower case matches either case. **Enter** keeps it, shown in the path bar; **Esc** puts back the filter there was; an empty one shows everything again. `..` always stays. What is selected but filtered out is let go, so a copy or delete never takes what cannot be seen. The filter belongs to its directory: rereads are narrowed too, Ctrl+U takes it along, and going anywhere else drops it
- 🌳 **Ctrl+B flat view** - every file under the panel's directory in one list, as Total Commander's branch view, each by its path from there (`sub/deep/notes.txt`). Sorted by size (Ctrl+F6), it finds what is taking the space. Directories are walked rather than listed; links to them are not followed, nothing in `/proc`, `/sys` and the like is gone into, and what is hidden stays hidden unless F11 shows it. Copy, move, delete, view, edit, compare and select work on the files as anywhere - F5 copies them without the directories they are in - and F2 renames one where it is. Inside an archive too. The path bar says `flat`; it combines with Ctrl+S, so `*.rs` across a whole tree works. Patterns, there and for `+` and `-`, go by each file's own name, so `test_*` finds every test file however deep; one with a `/` inside it, as `src/*/*.rs`, and a plain word in the filter go by the path. Ctrl+B again goes back, onto what holds the file the cursor was on, and going anywhere else drops it. A tree too big to wait for gets **Esc** as any slow directory does, and the list stops at 100000 files, saying so

## 🔭 Find Files (Alt+F7)
- 🎯 **By name, and by what is in them** - a name pattern as `+` takes it (`*.jpg;*.png`, `*/` for directories), and text the file has to hold, lower case matching either case. **Ctrl+F7** works too, for desktops that take Alt+F7 for moving windows. The last search is offered again
- 🧪 **Or by a regular expression** - the switch under the fields makes Containing one, as `^(pub )?fn \w+\(`: `^` and `$` are each line's ends, and lower case matches either case. One that is not an expression says why, and the form stays to put it right
- 📏 **By size and by age** - Size as `>10M`, `<1K`, `>=`, `<=` or `1M..10M`, in K, M, G and T of 1024, `1.5G` too; Modified as an age - `<7d` in the last week, `>1y` older than a year, `1d..7d` between, in `min`, `h`, `d`, `w`, `mo` and `y` - or a date: `2026-10-01` that day, `>2026-10-01` after it, `<` before it, `>=` and `<=` it included, `2026-10-01..2026-10-31` from one to the other, the days whole. Directories have no size, and are left out of a search by it. An empty field asks for nothing. **Tab** and **Shift+Tab** go through the fields and the switch, **Space** turns it on
- 🌳 **Down from the panel you are in** - each directory's contents straight after it, in the order the panels list them, as `find` lists a tree. Links to directories are not followed, and hidden entries are passed over unless F11 shows them. The system's own trees - `/proc`, `/sys`, `/dev` and `/run`, all but `/run/media` - are left out unless the search starts in one: their entries pass for files and are not, and some never answer a read
- 🪶 **Never in the way** - it runs on a thread of its own, and results arrive as they are found while it says where it is looking. Files are read 64 KiB at a time, never whole, and pipes and devices are never opened. Directories that cannot be read are counted, not fatal
- ↩️ **Enter goes there** - the panel moves to the directory of the result chosen, cursor on it. Esc closes the list, stopping a search still under way
- 📥 **F feeds them to the panel** - what has been found so far, in the active panel as one list under the directory the search started in, each by its path from there, as Ctrl+B lists - to be copied, moved, deleted, renamed or selected together. The path bar says `found`. A reread drops what has gone since, and a rename keeps the file in the list under its new name; Ctrl+B, or going anywhere else, goes back to the directory as it is

## 👯 Duplicates (Alt+D)
- 🔍 **Files the same as another** - under the panel's directory, or among what is selected: grouped by size first, which costs nothing, and only those of a size another has too are read and compared by SHA-256, as a job with the progress bar and Esc
- 🧹 **Ready for F8** - the groups are fed to the panel, as Find files feeds it, with every one of a group selected but the one nearest the top. Empty files, links, and second names of one file - hard links - are left out: deleting one of those would free nothing, or leave a link to nothing. What cannot be read is left out, and the end says how many

## 🗂️ Dossier (Alt+R)
- 📋 **The directory summed up** - its files, directories and size; what kinds of file take its room, each with a bar and its share; the five largest and the five newest; the languages its code is in, by lines; how many commits git has had in it a week, over the last eight; and how many files are copies of another, and the room they take. Worked out as a job, with the bar and Esc; `.git` is not gone into, and files over 8 MiB are not read for lines. **↑**/**↓**, PageUp/PageDown and Home/End scroll it, **Esc** closes it

## 📼 Mixtapes (Alt+B)
- ➕ **Gathered from anywhere** - **Alt+B** puts what is chosen on the tape playing, whichever directory it is in, and says which tape and how many it holds. With no tape yet, it starts one called Mixtape
- 📼 **Listed with Alt+Shift+B** - every tape by its name - "Release files", "Tax 2026", "Photos to sort" - with how much is on it, the one playing marked ▶. **Enter** or **1**…**9** shows a tape in the panel and plays it; **Space** plays one without showing it; **N** or **Insert** starts a new one, named where it is listed, which plays; **R** or **F2** renames one; **D** or **Delete** removes one - the tape, never the files on it. A name another tape has is refused
- 🧺 **Shown in the panel** - fed as Find files feeds it, under the directory all of it is in, every entry selected, for **F5**, **F6** or **Alt+P** at once - each copied or packed under its own name. Alt+B there takes entries off the tape, never off the disk; Alt+Shift+B again goes back
- 💾 **Kept across runs** - in the `mixtapes` file beside the config, written as they change. Every tape follows its files as they are renamed and moved in fm84; what is gone is let go of when the tape is shown

## 👻 Ghost Hunt (Alt+Shift+G)
- 🕸️ **What nobody has opened in years** - the files under the panel's directory, or among what is selected, last read and last written more than two years ago - a file written last month is not a ghost, whatever its access time says. Fed to the panel oldest first, each drawn faded with a ghost beside it
- 🧹 **A clean-up list** - nothing is selected: what to let go of is picked one at a time, not one F8 away from all of it. A file with more than one name is there once
- ⏱️ **Where the times are kept** - refused on a filesystem mounted `noatime`, which never updates when a file is read, so everything would look as old as it was made. `relatime`, the usual, keeps them close enough for years

## 🗑️ The Trash (Alt+T)
- 📂 **A folder of its own** - **Alt+T** opens the system's trash in the panel at `~/@trash`, which is not on the disk, gone into as an archive or a git commit is. Everything is listed by the name it had - two of one name told apart as `name (2)`, the latest keeping the name - and the Modified column says when it went. **Alt+T** again goes back where the panel was
- 👀 **Looked into** - **F3** views a file, **F5** copies out, and a directory in the trash is gone into and copied out of as any is
- ↩️ **Put back** - **F6**, or **Enter** on a file, puts what is chosen back where it came from, as a job; one whose place has been taken since is asked about, never written over
- 🔥 **Emptied** - **F8** deletes what is chosen for good, always asked first. Only the whole of what went to the trash is put back or emptied, not what is inside a directory in it
- 👀 **Live** - the panel is read again as the trash changes, whatever put something in it or took it out
- 🍎 **On macOS** - with Full Disk Access for the terminal fm84 runs in, in System Settings, Privacy & Security, the trash is looked into, copied out of and emptied, but not put back: macOS does not say where things came from. Without it, fm84 says what is wanted

## 🌳 Directory Tree (Alt+F10)
- 🌲 **As ncd drew it** - **Alt+F10**, Norton Commander's tree key, turns the panel into the tree of its drive's directories, from its root, opened down to where the panel is, the cursor there and that directory in bold. Inside an archive, a git commit or the trash, the tree is of that, from its top. Only directories, by name; hidden ones as F11 says
- ↔️ **Opened and closed** - **→** or **+** opens the directory under the cursor, or goes into it when it is open; **←** or **-** closes it, or goes up to the one it is in. Marks say which: ▾ open, ▸ closed or not read yet, … being read, ─ nothing in it
- 📤 **The other panel follows** - **Enter** sends the other panel to the directory, and the tree stays, to go on choosing. **Esc** or **Alt+F10** again lists files, in the directory under the cursor
- 🔍 **Typed to** - letters go to the first directory on show whose name starts with them, **↑** **↓** to the others, as the panels' quick search
- 🌳 **All of it** - **`*`** opens everything below the cursor, as a job with **Esc**: links to directories are listed but not gone through, other filesystems - `/proc`, network mounts - are left alone, and it stops at 5000 directories
- 📝 **Acted on** - **F5** and **F6** copy and move the directory to the other panel, **F7** makes one inside it, **F8** deletes it - inside an archive as they do there. Never the top of the tree
- 🖱️ **The mouse** - a click puts the cursor on a row, one on its mark opens or closes it, a double click is Enter, and the wheel moves the cursor
- 🪶 **Never in the way** - a directory is read the first time it is opened, on a thread: one on a mount that does not answer shows … and holds nothing up. After a job, and Ctrl+R, what is open is read again

## ✂️ Split and Join
- 📏 **Too big for where it goes** - before a copy or a move writes anything, a file larger than the drive it goes to holds in one - past 4 GiB onto FAT, told on Linux, macOS, the BSDs and Windows - is asked about: **P** splits it, **S** skips it, **Esc** stops
- 🧩 **In pieces** - `name.001`, `name.002` and on, 4095 MiB each, with `name.sha256` beside them listing each piece, as `sha256sum -c` and Alt+H read it. Verified copies read each piece back. A move takes the file away once all of it is there
- 🔗 **Joined back** - **F5** on a `.001`, with a `.002` beside it, offers to join them into the file they were cut from in the other panel; each piece is checked against the `.sha256` as it goes through, and one that does not match, or is missing, leaves nothing. Copied to a name ending in `.001`, it is that piece copied as it is

## 🔄 Synchronize Directories (Alt+S)
- ⚖️ **All the way down** - the two panels' directories compared on a thread of its own, the plan filling in as differences are found and saying where it is looking. An entry on one side only is a difference, and is not gone into; a directory on both is gone into. Two files differ when one is newer, or when they are the same age and not the same size; times two seconds apart count as the same, as FAT keeps them. Links are compared as the links they are, never followed, and hidden entries are left out unless F11 shows them
- 📋 **A plan, row by row** - each path, both sides' sizes and dates (the dates go when the popup is too narrow), the newer side brighter, and between them what is to happen: `──▶` copied to the right, `◀──` to the left, `✗ del` deleted, `≠` left as it is. What is missing on one side is copied there, and the newer of two files over the older; two of the same age, and a file meeting a directory, are left for you to say. The foot counts each kind
- ⌨️ **Change it** - **→** and **←** copy that way, **Delete** or **D** deletes from the side that has it alone, **Space** or **=** leaves it, each moving on to the next row so a run is set by holding the key. **>** makes the right as the left is - everything copied across, what only the right has deleted - and **<** the other way; **R** puts back what the compare said. Arrows, PageUp/PageDown and Home/End move about
- ▶️ **Enter runs it** - as one job, with the progress bar and Esc, writing over what is in the way and deleting to the trash when F11 says so. A plan that deletes asks for a second Enter first, unless Confirm delete is off; any other key takes the first back. Both panels are read again after
- 🚫 **Not everywhere** - not inside an archive, and not with one directory inside the other, which copying across would copy into itself - through a link too

## 📝 File Operations
- **F1** 💡 - Help/About: the keys, then what fm84 is - its version, licence and where it lives - and last its high scores, as an arcade cabinet lists them: bytes copied and moved, files renamed, things deleted, copies found, the longest job and the jobs done, then eight achievements, starred once had. INSERT COIN while there is nothing on it. They are counted as the jobs finish, and kept in `scores` beside the config. Like every popup it sits over the panels, no taller than they are; when the list is longer, the arrows, PageUp/PageDown, Home/End and the wheel scroll it, and the corner says which lines show
- **F2** ✏️ - Rename files & folders (arrows, Home/End, Backspace and Delete while typing, the field scrolling to keep the cursor in view on a long name); a change of case alone works on macOS and Windows too
- 🏷️ **F2 with a selection** - every name selected changed at once, by a pattern: `[N]` the name, `[E]` the extension, `[C]` a counter, with **Find** and **Replace** after it and a change of case last - lower, UPPER, First letter or Title Case. `[N2-5]` is the name's letters 2 to 5, `[N3-]` from the third on; `[C10+5:3]` counts from 10 by fives in three digits, `010`, `015`… A table of old names beside new ones follows every key, and a name that cannot be had - one given twice, one something else already has, one that is not a plain name - is marked in red, and nothing is renamed until none is. `[N].[E]` with no extension leaves no dot. Names that go where another is leaving - `1` to `2` while `2` goes to `3` - are moved through names of their own first, so none is written over; and where a drive takes two names for one that the table told apart - a FAT stick on Linux taking `ax` and `Ax` for the same - the second is refused and named, and the first stays. **Tab** goes through the fields, **←**/**→** the case, **Enter** renames, **Esc** leaves them be
- 🖼️ **Names from inside the files** - in the pattern, `[Exif:date]` is when a photograph was taken, as `2026-03-14 18.02.11`, `[Exif:day]` and `[Exif:time]` its halves, `[Exif:make]` and `[Exif:model]` the camera - from JPEG, PNG, WebP and raw files; `[Tag:artist]`, `[Tag:title]`, `[Tag:album]`, `[Tag:track]` (two digits) and `[Tag:year]` from MP3, FLAC, Ogg and M4A tags; `[Pdf:title]` and `[Pdf:author]` from a PDF. Each file is read once, only its head. A character no name can hold becomes `-`, and a file that does not say what is asked is marked *not in the file* rather than left with no name
- **F3** 👁️ - View files (text, hexdump, or images as ASCII art); Esc closes the viewer, F3 inside it finds the next match
- **F4** 📝 - Edit files with **syntax highlighting** (Ctrl+S to save, Esc to close with an unsaved changes prompt, mouse click to position cursor)
- **F5** 📋 - Copy (selected items or cursor item), keeping permissions and modified times where the filesystem can hold them
- **F6** 📦 - Move (selected items or cursor item); a move to another disk keeps modified times too, so it looks just as a move on one disk does
- 🎯 **Where to** - F5 and F6 ask where, with the answer filled in: for a single file its path in the other panel, ready for a new name; for anything else the other panel's directory. Enter alone sends it there. Read as `cp` and `mv` read it: into a directory that is there, or one typed with a `/` on the end; anything else is a new name for the one item. A path that is not absolute starts from the panel you are in, so a bare name copies beside the original - and F6 with one renames it. `~` is home
- ♻️ **Names already taken** - each file already there is asked about as the job reaches it, with both shown, size and date and which is newer: **Y** overwrite, **N** skip, **K** keep both, **A** overwrite all, **S** skip all, **B** keep both all, **O** overwrite all older, **Esc** abort. Keep both leaves what is there and writes the new one beside it as `name (2).ext` - `src (2).tar.gz` for an archive, `.bashrc (2)` for a dotfile - numbering on past any already taken. Directories are merged, and asked about file by file. F11 can make it overwrite, or refuse the whole job, without asking
- 📊 **Progress while copying, moving and deleting** - a bar with the current file, how far along it is and the transfer rate; Esc cancels. Each file is written beside its destination and renamed into place only once it is whole, so a copy that is cancelled, fails or is cut short by quitting never leaves half a file under the real name. The work runs off the interface thread, so a slow or stalled disk cannot freeze the display
- 💽 **Room checked first** - before a copy, a move to another disk or Alt+S writes anything, what it will write is added up for each filesystem it goes to and set against what can still be written there. One without the room says how much is needed and how much is free: **R** looks again once some has been made, **C** goes on anyway - a file written over gives its room back, and a filesystem may compress - and **Esc** stops, the reason left in the status bar. A move within one disk renames, and needs no room
- ✔️ **Verify copies** - with the F11 option on, each file a copy, a move to another disk or Alt+S writes is read back from where it went and its SHA-256 compared with the original's, before it takes its place. The copy is flushed to the device and let go of from memory first, so what is read is what the device kept - on Linux and the BSDs; macOS reads past its cache. One that reads back differently is thrown away and asked about as any failure is, so a move never deletes an original whose copy is bad. The bar counts each byte twice, copied and read back. Slower, as every file is flushed on its own: for USB sticks and network mounts
- 🧯 **One bad entry doesn't sink the job** - a file that will not copy, move or delete (a socket, a pipe, a permission refused, a disk full) stops the job and asks: **R** retry, **S** skip, **A** skip all, **Esc** abort. A skipped entry is left where it was, and a directory holding one stays with it, so a move never leaves anything gone from both sides. The end says how many were skipped
- 🚪 **A way out of an operation that will not finish** - F10 during one offers to leave; a second F10 takes it, for a disk that has stopped answering and never notices the cancel
- **Alt+F5** 🔗 - Make a symbolic link to what is chosen. **Ctrl+Shift+F5** works too, as in Total Commander, where the terminal lets it through - kitty keeps it for reloading its config. It asks where, as F5 does, opening on the entry's name in the other panel - a directory too, since the link is the new entry - or, for several, on the other panel's directory, with a link in it for each. Each points at the absolute path of what it links to. **Tab** makes hard links instead - another name for the same file, which outlives the original; files only, on the same filesystem, and of a symbolic link the file it points at. Nothing already there is written over: an entry that cannot be linked is named, and the rest are still made. On Windows a symbolic link takes Developer Mode or the right to make links
- **Shift+F2** ⚖️ - Compare directories, as in Total Commander: each panel selects what differs from the other - an entry only it has, and of a file both have, the newer one, or both when the times agree and the sizes do not. Times within two seconds count as the same, as FAT keeps them no finer. Directories both have are not gone into. What was selected before is replaced, ready for F5 to copy across, and the status bar says how many differ
- **Ctrl+Z** ↩️ - Undo the last rename, copy, move or move to the trash - and Ctrl+Z again the one before, up to 32 jobs back. A copy is deleted, a move or a rename put back - names that swapped or went round in a chain together - and what went to the trash restored from it, on Linux and Windows; macOS cannot look through its trash, and says so. A step whose target has changed since - a copy written into, another entry where a moved one was, a file moved back where something now stands - is refused and asked about; a file or a directory moved, and worked on since, still goes back: **R** looks again, **S** leaves it, **Esc** stops. What wrote over a file, or merged into a directory, is not kept to undo, as taking it back would take what was there too
- **Ctrl+E** 📝 - The panel's names in the editor, a numbered line each, as vidir has them: edit a line to rename, delete it to delete, duplicate it to copy; a directory ends in `/`. Saving shows the plan - every rename, copy and delete - and **Enter** runs it as one job: the deletes first, to the trash as F8 goes, then the renames together, so names can swap, then the copies. **Esc** goes back to the lines. A line that cannot be had - no number, a name twice, one already taken - says which, and nothing runs. Ctrl+Z takes it all back. Not in Ctrl+B's view, nor inside an archive
- **F7** 📂 - Create new directories (**Shift+F4** for an empty file); same editing keys as rename
- **F8** / **Delete** 🗑️ - Move files & folders to the system's trash (selected items or cursor item, with confirmation - which F11 can turn off - and progress). What the trash will not take - a read-only disk, one with nowhere to keep a trash - is asked about, with **D** to delete it for good. F11 can make F8 delete permanently instead
- **Shift+F8** / **Shift+Delete** 💀 - Delete permanently, always asking first; with F11's Burst what is deleted for good on, the rows burst into pixels first
- **Alt+H** #️⃣ - Checksums of what is selected, or of the file under the cursor, a directory's files all the way down. SHA-256, SHA-512 and MD5 are all worked out in one reading of each file, as a job with the progress bar and Esc, and shown in one popup - wrapped, never cut, however long - with the algorithms in a row above them: **Tab** or **→** shows the next one's, **Shift+Tab** or **←** the one before, at once. **C** copies them - one file's checksum alone, for pasting where it is to be compared - and **Enter** writes them as `sha256sum` does, to `name.sha256` for one file or `SHA256SUMS` for several, and lands on it; a name already taken goes by F11's When destination exists. On a checksum file - `*.sha256`, `*.md5`, `SHA256SUMS` and the like, written by `sha256sum`, `md5sum` or in BSD's `SHA256 (name) = …` - it checks the files it names instead, and says what failed, what is missing and what is OK, the failures first. What cannot be read is listed as such, not asked about. Inside an archive, copy out first
- **Alt+A** 🔐 - Change attributes, as in Total Commander: the permissions, owner, group and modified time of what is selected, or of the entry under the cursor. Each field opens on what the entries have in common, and one left as it is, or emptied, changes nothing. The mode is octal (`755`) or as `chmod` takes it (`u+x,go-w`, `a=rX`), so several entries whose modes differ can each gain or lose a bit; with one entry, what it comes to is shown beside it. Owner and group go by name or number, and the time as `2026-10-23 14:02:11`. **Tab** or a click moves between the fields, a click putting the cursor where it lands. Something typed that cannot be read is said so before anything changes; an entry that refuses is passed over and named. On Windows only the time
- **F9** 💻 - Open external terminal in current directory (which one is set under F11)
- **Alt+M** 🧾 - The user menu: commands of your own, as F2 is in Midnight Commander, kept in `menu` beside the config, a line each as `label = command`. Each runs in the shell, in the panel's directory, with fm84 out of the way until Enter is pressed after it; the panels are read again after. In the command, `{file}` is the entry under the cursor, `{name}` its name alone, `{files}` what is chosen - the selection, or else the entry under the cursor - `{dir}` the panel's directory and `{other}` the other's. They go in as variables the shell expands, never pasted in as text, so a name with spaces, quotes or a `$` in it arrives whole - quoted or not: `"{file}"` and `'{name}.bak'` are one word as `{file}` is. `{}` is the shell's own, as in `find -exec`. A command that needs an entry says so when there is none, or when the panel is inside an archive. **Enter** or **1**…**9** runs one, **E** edits the menu, which the first Alt+M makes with examples
- **F10** 🚪 - Exit to the void - asking first about unsaved changes in the editor. **Shift+F10** leaves `cd84` in the directory it started from
- **Space** / **Insert** ✅ - Select/deselect files for batch operations
- **+** / **-** / **\*** 🎯 - Select or deselect by a pattern such as `*.jpg;*.png` (`*`, `?`, `[a-z]`, `[!0-9]`; lower case matches either case), or invert the selection of files - **Alt+\*** inverts directories too. Patterns pick files; end one with `/` for directories, as in `*/`. Once a quick search is under way, `-` types into it instead
- 📋 **Ctrl+C** / **Alt+C** - copy the full paths, or just the names, of what is selected - or of the entry under the cursor - to the clipboard, a line each; on `..`, the panel's own directory. It goes over OSC 52, so it reaches the system clipboard over SSH too, and the built-in editor pastes it either way
- 🖱️ **Double-click** - open directories and archives, or open files as Enter does
- 🖱️ **Mouse scroll** - scroll content in Viewer, Editor, and file panels

## 🔄 Live Panels
- 👀 **Automatic refresh** - panels notice when their directory changes on disk and reread themselves, and the preview and the detail lines are gathered again with them
- ⌨️ **Ctrl+R** - force an immediate reload of both panels
- 🧭 **Vanished directories** - if the open directory is deleted, the panel climbs to the nearest surviving parent
- 🤫 **Stays out of the way** - never reloads while a dialog, Viewer or Editor is open
- 🐌 **Slow and dead mounts** - directories are read, watched and described on threads of their own. A network mount that stops answering no longer freezes fm84: the panel keeps showing what it did, the status bar says it is reading, and Esc stops waiting. The other panel works as ever

## 🧱 Columns
- 📋 **Name, Ext, Size, Modified, Attributes** - permissions written the way `ls -l` writes them
- 📐 **Priority when space runs short** - columns drop from the right, Name always stays and keeps the leftover width
- 🧮 **Info** - a column filled by your own commands, by extension, from the `columns` file beside the config, as `jpg png webp = identify -format '%wx%h' {file}`: the first line the command prints. F11 turns it on, and **E** on its row there edits the file, which comes with examples - a picture's size, a song's length, a PDF's pages, a file's lines, its last git change. The commands run on a thread of their own once the listing is in, two seconds each at most, and what they give is kept until the file or the command changes. Sorted by, numbers count as numbers - `9:58` before `10:02` - and what has no value goes last
- 🔃 **Sort from the panel** - **Ctrl+F3** by name, **Ctrl+F4** by extension, **Ctrl+F5** by date and **Ctrl+F6** by size, as in Total Commander, or click a column heading; the same one again turns the order round. The heading sorted by carries an arrow, ↑ or ↓, and both panels follow, kept as F11 keeps it
- 🎛️ **Your choice of them** - F11 turns each one off, and sets how dates and sizes are written
- 🔤 **Any name the filesystem allows** - a name that is not valid UTF-8 is shown as near as it can be read and still opens, renames, copies and deletes as itself; operations work from the name the filesystem holds, never from what it looked like on screen - selection, the F4 and F9 commands and remembered directories included
- 🛡️ **Names neutralised** - a file name can hold anything but `/`, escape sequences and tabs included. They are drawn as dots rather than sent to the terminal, wherever a name appears: the rows, the detail lines, the preview, the titles and every popup

## 📊 Status Bar
- 📈 **Panel stats** - selected/total file count and size shown per panel
- 💽 **Disk usage** - a meter and used/total for each panel's filesystem, shortening then stepping aside on narrow terminals
- 🎨 **Active/inactive styling** - active panel stats highlighted, inactive dimmed
- 🎹 **Key bar** - the F-keys along the bottom border, as in Midnight Commander: those the panels, the Viewer or the Editor answer, F8 named Trash or Delete as F11 has it. Click one to press it. On a narrow terminal they drop off whole from the end. Each F-key is drawn in a colour of its own beside its name, as the keys are in F1, in every popup and in the Viewer's and Editor's bars

## 🔎 Detail Lines
- 📋 **Two lines under the panels** - what the columns have no room for: the whole name however long, the exact byte count, the timestamp to the second, `owner:group`, the permission bits, and where a symlink points
- ✂️ **Narrow terminals** - whole fields are given up from the right rather than cut mid-figure, and the name shortens from the front so the extension survives

## 🎨 Viewer (F3)
- 🖼️ **Bordered frame** with filename title bar
- 📊 **Line numbers** in the gutter (F11 can hide them)
- 🔢 **Status bar** - filename, line count, file size, detected syntax
- 🔢 **Hex view** - binaries open as a `hexdump -C`; `X` toggles hex for any file, so you can eyeball a BOM or CRLF endings
- 🖼️ **Images as ASCII art** - PNG, JPEG, GIF, WebP and BMP drawn in colour, each character on its own coloured background so the dark parts keep their colour; `X` cycles Image, Text and Hex, `F` switches between fitting the whole picture in, centred, and filling the viewer; which one a picture opens with, and whether backgrounds are drawn, is set under F11
- 📄 **Step through a folder's pictures** - PageUp and PageDown move to the next picture and the previous one, wrapping round and stepping over anything that is not one; the neighbours are decoded ahead so each arrives without a pause (F11 can turn that off)
- 🖱️ **Drag a picture** - hold the mouse down on it and it follows the pointer, both directions at once
- 📐 **True proportions** - the shape of a picture is worked out from the size of your terminal's cells, which it is asked for, rather than from an assumption about them; a terminal that will not say gets the usual 2:1
- 🔍 **Zoom** - `+` and `-` scale a picture from a quarter of the fitted size to four times it, keeping whatever is in the middle of the view in the middle
- 🖱️ **Mouse selection** - drag to select, Ctrl+C to copy
- 🔎 **Find** - Ctrl+F asks what to look for, F3 and Shift+F3 go to the next and previous match, round the ends of the file. Every match on screen is underlined and the current one selected, ready for Ctrl+C. Lower case matches either case, a capital only itself. In hex view it searches the dump as shown
- 🔢 **Go to line** - Ctrl+G, then the number
- 🛡️ **Escape sequences neutralised** - a file full of control codes can't hijack your terminal
- 🔤 **Stray bytes** - a text file with a byte that is not UTF-8 in it still opens, with a placeholder where the byte was; `X` shows it as it is
- ❓ **Large file prompt** - asks before pulling anything over 64 MiB into memory (16 or 256 under F11), and before decoding a picture that needs over 256 MiB of it - a few hundred KB of PNG can unpack to hundreds of MB
- ↔️ **Horizontal scrolling** - Left/Right keys and mouse scroll wheel, stopping at the longest line
- ┃ **Scroll bars** - drawn into the frame's border, down the right for the lines and along the bottom for the columns, each only when there is more than fits; the text keeps every column it had. Click the track for a page that way, or drag the thumb, which follows the pointer until the button comes up. F11 sets what the thumbs are drawn with
- 📜 **Wrap** - `W` breaks long lines onto as many rows as they need, after a space where there is one; scrolling goes by rows, so a line longer than the screen can be read to its end. Finding, selecting and copying go on by whole lines, so a copy never gains a break that was only on screen, and line numbers and Go to line count lines, not rows. The next file opened wraps or not as the last was left
- 📡 **Follow** - `F` on text follows the file as it grows, as `tail -f`: what is written to it comes onto the end a few times a second, and the view goes there - only when something comes, so a search stays put until then. A log cut short, or turned over for a new one, is read again from its start. Matches stay marked. Scrolling up, Home and PageUp stop it; the status bar says `F [Follow]`
- 🖱️ **Mouse scroll** - vertical and horizontal scrolling with the scroll wheel

## ✍️ Editor (F4)
- 🌈 **Syntax highlighting** for Rust, Python, JS, TS, JSON, TOML, YAML, Markdown, Shell, C/C++, HTML, CSS
- ⚡ **Incremental highlighting** - typing re-parses from the edited line, so speed doesn't fall off in long files
- 📏 **Highlighting limit** - files over 512 KiB open as plain text, since the first parse takes about 0.9s per MB; F11 moves it to 256 KiB or 2 MiB, or turns highlighting off
- ↩️ **Line endings preserved** - a CRLF file stays CRLF when saved
- 🖼️ **Bordered frame** with filename and modified indicator in title bar
- 📄 **Full text editing** - cursor navigation, insert, delete
- ✂️ **Select, cut, copy, paste** - Shift+arrows to select, Ctrl+A for all, Ctrl+X/C/V (or Ctrl+Insert, Shift+Insert, Shift+Delete)
- ↩️ **Undo and redo** - Ctrl+Z, then Ctrl+Y or Ctrl+Shift+Z, 200 steps deep, one step per action rather than per keystroke burst; a key that changes nothing costs no step
- 📋 **System clipboard** - copies reach it over OSC 52, pastes arrive as bracketed paste, both without linking a clipboard library
- 💾 **Save** - F2 or Ctrl+S, written beside the file and swapped in whole, so a full disk or a crash mid-save leaves the old file rather than half of the new one; links, permissions and owner are kept
- 🛑 **Changed on disk** - when something else has written the file since it was opened, a save stops and says so, the file as it was and as it is now: **O** overwrites it, **R** reloads it and drops the edits, **Esc** goes back to them. A file deleted meanwhile can be saved again with O
- 📍 **Line/Column tracking** - always know where you are
- ↩️ **Enter keeps the indent** - the new line starts as indented as the one it came from, as far as the cursor, so Enter in the middle of an indent does not make it deeper; a line left with nothing but its indent is emptied
- ⇥ **Indent lines** - **Tab** on a selection of lines indents each one a step, **Shift+Tab** brings them - or, with nothing selected, the cursor's line - a step back out. A step is a tab in a file indented with tabs, and F11's tab width of spaces otherwise; empty lines are left be. The lines stay selected for another press, and each press is one step to undo. Tab with nothing selected still types a tab
- 💬 **Comment lines** - **Ctrl+/** (Ctrl+_ or Ctrl+7, as most terminals send it) makes the selected lines, or the cursor's, comments with the file's own mark - `//` for Rust, C, Go, JavaScript and the like, `#` for Python, shell and config, `--` for Lua and SQL, `;` for Lisp and INI, `%` for TeX, `"` for Vim, `REM` for batch - at the shallowest indent among them, so a block stays lined up. When every line already is one, it makes them code again
- 🔎 **Find and go to line** - Ctrl+F, F3 / Shift+F3 and Ctrl+G, as in the Viewer; the match found is selected, so typing replaces it
- 🧪 **Regular expressions** - **Alt+R** in the Find or Replace prompt, in the Viewer too, switches between text and an expression, and the prompt says which. Lower case matches either case; one that is not an expression says why
- 🔁 **Replace** - Ctrl+R or F4 asks what to replace (the selection, or the last thing looked for) and what with, then goes from the cursor a match at a time: **Y** replaces, **N** skips, **A** replaces the rest, **Esc** stops. It goes round the end of the file and stops where it began, never into the text it has just put in; Enter is not an answer. Replace all is one step for Ctrl+Z. By a regular expression, the replacement fills in `$1`, `${name}` and `$0` from each match
- ⚠️ **Unsaved changes prompt** - Save/Discard/Cancel dialog on close, and on F10; a save that fails keeps the editor open, edits and all
- 🔤 **UTF-8 only** - a file that is not UTF-8 text is refused rather than opened with its odd bytes replaced, which saving would make permanent; F3 shows it
- ↔️ **Horizontal auto-scroll** - viewport follows cursor past the right edge
- ┃ **Scroll bars** - as in the Viewer: click the track for a page, drag the thumb; like the wheel they move the view and leave the cursor where it is
- 🖱️ **Mouse scroll** - vertical and horizontal scrolling with the scroll wheel
- 🖱️ **Mouse click and drag** - click to position the cursor, drag to select

## ⚖️ Compare Files (= or Shift+F3)
- 🎯 **Which two** - two files selected in the panel you are in; otherwise the file under the cursor against the one of the same name in the other panel, or failing that the one under the cursor there. The left panel's file is always on the left
- 🪞 **Side by side** - each file under its path, numbered as F11 numbers lines, with the mark `diff -y` uses between them: `|` changed, `<` only on the left, `>` only on the right. Lines that differ are shaded. Lines removed and added in one place are paired off, and whichever side has more carries on alone
- ⏭️ **From one difference to the next** - it opens on the first; **F3** or **N** goes to the next, **Shift+F3** or **P** to the previous, and the status bar says which it is on. Arrows, PageUp/PageDown, Home/End and the wheel scroll both sides together; **Esc** closes it
- 🧮 **The diff `diff` and git use** - Myers', on lines, after the lines both files start and end with are set aside. Two files that differ in more than 2,048 lines between those are shown as one block replaced
- 💬 **Nothing to show** - files that are the same, that differ only in line endings (CRLF against LF, or a missing newline at the end), or that are not text are only spoken of, in the status bar - for binaries, the first byte that differs. Either file over the size F11 asks before opening is refused
- ⌨️ **Shift+F3 needs a terminal that can send it** - most send F3 with a modifier as they report where their cursor is, and fm84 cannot tell the two apart. fm84 asks for kitty's keyboard protocol, which settles it, where the terminal has it - kitty, foot, WezTerm, Ghostty, Alacritty. Elsewhere, `=` (Ctrl+F3 sort and the Viewer's Shift+F3 have the same trouble there)

## 👁️ Preview (F12)
- 🪞 **Opposite panel** - shows the head of whatever the cursor is on, and follows it
- 📁 **Directories** - item count instead of contents
- 🔢 **Binaries as a hexdump** - no longer just "Binary file": the head of it in hex with the printable characters beside it, at 16, 8 or 4 bytes a row depending on how much room the pane has
- 🪶 **Bounded** - reads at most 64 KiB of a text file and 4 KiB of a binary, never prompts, never loads a whole file, and never opens a pipe or a device

## ⚙️ Options (F11)
Grouped under four headings, in a popup no taller than the panels: the list scrolls within it, with ↑/↓ or the mouse wheel, which stop at its first and last row, and the corner says which row of how many the cursor is on.

**Panels**
- 🙈 **Show hidden files** - dotfiles, or on Windows anything with the hidden attribute
- 🔃 **Sort by** Name, Extension, Size, Modified or Info, **ascending or descending**
- 📁 **Directories first** - or mixed in among the files
- 🔠 **Case-sensitive sort** - off by default, so `readme` and `README` sit together
- 🧱 **Ext, Size, Modified and Attributes columns** - each on or off; with Ext off, Name shows the whole file name
- 🧮 **Info column, from commands** - off until you turn it on; **E** on the row edits the commands, as under Columns
- 🏷️ **Git marks** - what git says of each entry, at the end of its name; on by default
- 📅 **Date format** - `dd/mm/yy`, `yyyy-mm-dd`, or relative (`3 h ago`)
- 📏 **Size units** - KiB (1024) or kB (1000), everywhere a size is shown

**Behaviour**
- 🗑️ **Confirm delete** and ✅ **Confirm copy and move** - turn off to skip the question
- ♻️ **Delete to trash (F8)** - on, F8 moves to the trash; off, it deletes for good. Shift+F8 always deletes for good
- ♻️ **When destination exists** - Ask about each file as the copy or move reaches it, Overwrite them all (directories merged), Keep both - each new file beside the one in its way, as `name (2).ext` - or Refuse a job with any name taken before it starts. Alt+P goes by it too, for an archive already at the name. A file never replaces a directory or the other way round, and nothing is copied onto itself
- ✔️ **Verify copies** - read each copied file back from the disk and check it against the original, as under File Operations
- 💻 **Terminal (F9)** - any command, `{}` standing for the directory; left empty, one is picked for you
- 📝 **Editor (F4)** - an external editor such as `nvim` or `hx`, which gets the terminal until it exits; `{}` stands for the file, which otherwise goes last. Left empty, the built-in editor opens
- 📍 **Remember directories** - reopen both panels where they were when fm84 last quit
- 👁️ **Preview on startup** - start with F12's preview open

**Appearance**
- 🌐 **Language** - **Automatic**, which follows `LANGUAGE`, `LC_ALL`, `LC_MESSAGES` and `LANG` (on Windows, mostly English), or one chosen, each named in its own words, English first and the rest in the order of the alphabet - a Greek or Cyrillic name by how it is spelt in Latin letters: **English**, **Български**, **Čeština**, **Dansk**, **Deutsch**, **Ελληνικά**, **Español**, **Français**, **Gaeilge**, **Hrvatski**, **Italiano**, **Magyar**, **Македонски**, **Nederlands**, **Norsk bokmål**, **Polski**, **Português (Brasil)**, **Română**, **Slovenčina**, **Slovenščina**, **Српски (ћирилица)**, **Srpski (latinica)**, **Svenska** or **Türkçe** - `bg`, `cs`, `da`, `de`, `el`, `es`, `fr`, `ga`, `hr`, `it`, `hu`, `mk`, `nl`, `nb` (or `no`), `pl`, `pt`, `ro`, `sk`, `sl`, `sr`, `sv` and `tr` in a locale. Serbian is in the Latin alphabet unless the locale asks for Cyrillic, as `sr@cyrillic` or `sr-Cyrl` does. Every word fm84 shows changes at once, counts in the forms each language gives them - French and Portuguese count nothing as one, Slovenian has a form for two, Polish tells 22 pliki from 21 plików, Irish sets 7 to 10 apart (7 gcomhad, 3 chomhad), Romanian says 20 de fișiere. The names of keys are written as each language's keyboards print them (Strg in German, Entrée in French, Mayús in Spanish); the keys themselves stay the keys, so `Y`, `N` and `A` answer whatever the words beside them say. The translations are built into fm84 itself, nothing to install beside it
- 🎨 **Theme** - switched on the spot, 18 of them:
  - fm84's own: **Synthwave**, **Outrun**, **Vaporwave**, **High contrast**, **Military**, **Picard**, **Pacman**
  - dark: **Dracula**, **Monokai**, **Nord**, **Gruvbox Dark**, **Solarized Dark**, **Tokyo Night**, **Catppuccin Mocha**
  - light: **Solarized Light**, **Gruvbox Light**, **Catppuccin Latte**, **GitHub Light**
  - each brings its own background, gutter and syntax colours; on a light one, extension colours darken and pictures draw dark ink on the light background
- 🖌️ **Background** - the theme's own, or the terminal's for a transparent or custom one. A light theme needs its own: on a dark terminal its text would all but vanish
- 🔣 **Icons** - Nerd Font, Nerd Font Mono (drops the padding a wide glyph needs, so icons stay centred), or Plain letters for a terminal without a Nerd Font
- 🕐 **Clock** - 24-hour, 12-hour, or off
- ▏ **Cursor** - in every field being typed into and in the editor: the terminal's own cursor as a **Bar**, a **Block** or an **Underline**, or **Classic**, the reversed cell fm84 drew before, for a terminal that cannot be told a shape (the Linux console). On exit the terminal gets its own shape back
- ✨ **Cursor blinks** - on or off. How fast, and whether at all, is up to the terminal: kitty's `cursor_blink_interval 0` keeps it still whatever this says
- 🚗 **Outrun progress bar** - a job drawn as a car driving down a neon grid towards the sun, in the theme's colours: the further it has got, the more is done, and the bigger the sun. Esc swerves it off the road. Off by default
- 💥 **Burst what is deleted for good** - the rows burst into pixels for a moment before a delete for good takes them; never for the trash. Off by default
- ⚡ **Turbo** - every theme's neon turned up - on a light one, only stronger - scanlines over the panels, and the logo blinking in F1. Off by default
- 🌃 **Night drive when left alone** - left alone on the panels for 1, 3, 5, 10, 15 or 30 minutes, fm84 drives down the Outrun grid: palms going by, the sun on the horizon and the logo over it, as Turbo draws when it is on. Any key or the mouse, and the panels are back as they were - that key doing nothing else. Not over a dialog, a job, the Viewer or the Editor. Off by default

**Viewer and editor**
- ⇥ **Tab width** - 2, 4 or 8 columns, in the Viewer, the Editor and the preview
- 📊 **Line numbers** - on or off, in the Viewer and the Editor
- ┃ **Scroll bars** - what their thumbs are drawn with: **Heavy** `┃━`, the border's own line drawn thicker, **Double** `║═`, **Dashed** `╏╍`, **Block** `█`, **Shade** `▓`, or **ASCII** `#` for a font without box drawing
- 🌈 **Highlight files up to** 256 KiB, 512 KiB or 2 MiB, or never
- ❓ **Ask before opening over** 16, 64 or 256 MiB
- 🖼️ **Images open as** Fit or Fill
- 🎨 **Image backgrounds** - on or off. On, each character sits on its own colour, so the dark parts of a picture keep theirs instead of showing the terminal through the gaps in the glyphs. Off costs less to send, which matters over a slow link
- ⚡ **Read pictures ahead** - decode the pictures either side of the one open, so PageUp and PageDown do not wait for each. Costs a few megabytes and a thread that wakes only while a picture is open

- ⌨️ **Up/Down** to move, **Enter**, **Space** or **Left/Right** to change, Enter again to save a typed command
- 💾 **Saved as you go** to `~/.config/fm84/config` (`$XDG_CONFIG_HOME` if set, `%APPDATA%\fm84\config` on Windows) - plain `key = value` lines, fine to edit by hand. Remembered directories go in `session` beside it, bookmarks in `bookmarks`, Alt+M's commands in `menu`, the programs files open with in `open`, the Info column's commands in `columns`, and F1's high scores in `scores`

## 📦 Archives
- 📂 **Gone into like directories** - Enter on a `.zip`, `.7z`, `.tar`, `.tar.gz`, `.tar.zst`, `.tar.xz` or `.tar.bz2` (and `.tgz`, `.tzst`, `.txz`, `.tbz2`) opens it in the panel, and its directories open as any do. The path runs through it - `~/photos.zip/2024/june` - so tabs, history, bookmarks, Ctrl+L and remembered directories all work inside one, and Backspace at its top comes back out onto the archive
- 📋 **Copied out with F5** - to the other panel, or wherever the dialog is told, a directory whole, asked about files in the way as any copy is, with the same progress bar and Esc. Times and permissions come out as the archive kept them; links come out as links
- 📤 **All of it with Alt+F9** - as in Total Commander, the whole of the archive under the cursor, or of the one the panel is in, into the other panel or wherever the dialog is told. **Ctrl+F9** too, for desktops that take Alt+F9 for hiding a window
- ⚖️ **Compared with Shift+F3** - a file inside an archive against one on the disk, or inside another archive: each is copied out first, and the diff is headed with the paths the panels show
- 🗜️ **Every way a tar is packed** - gzip, zstd, xz and bzip2, each read on past its first stream, so files joined end to end - as pigz, pzstd and pbzip2 write them - are one archive. A 7z is listed from its header without unpacking anything; one packed solid, as 7-Zip does by default, unpacks what comes before a file to reach it, which the progress bar covers
- 👁️ **F3, F12 and the detail lines** - a file is copied out to a scratch directory and shown, the preview reads the head of it, and the lines under the panels give its exact size, time, mode and, from a tar, its owner. Enter or Ctrl+O open it with the system's program the same way. The scratch directory goes when fm84 quits
- 📏 **Sizes at once** - Space and Alt+Shift+Enter size directories inside an archive from what it says, with nothing to walk
- ✍️ **Written into** - **F5** and **F6** copy and move into an archive the other panel is in, or one a typed path runs through - `~/box.zip/docs/`, the separator on the end or not; **F7** and **Shift+F4** make a directory or an empty file inside one, and land on it; **F8** and **Delete** delete from one, always asking first, whatever F11 says, as there is no trash to go to. A name already there is asked about as any copy asks - or as F11's When destination exists says - and two directories are merged; a file and a directory in each other's place are refused. The archive is written again beside itself and put in its place whole, so a cancel or a failure leaves it as it was, byte for byte, and what stays is carried across as it is: a zip's entries still compressed, or encrypted, a tar's headers byte for byte - owners, long names, a size kept past 8 GiB, and hard links, which take what they name with them when it is deleted. New entries go in at Normal. A move takes off the disk only what went in, as it was. Not from inside another archive: copy out first
- 🗃️ **Made with Alt+P** - what is chosen, packed into a `.zip`, `.7z`, `.tar.gz`, `.tar.xz`, `.tar.bz2`, `.tar.zst` or `.tar`, as a job with the progress bar and Esc. The dialog opens on the other panel's directory with a name from what is packed - a file's without its ending, a directory's, or for several the one they are in - and **Tab** goes through the formats by the ending of the name, `.tgz` and the other short ones too. Under the name, gone through with **↑** **↓** and changed with **Space** or **←** **→**:
  - 🎚️ **Compression** - Fast, Normal or Best, each format's own levels 1, 6 and 9; kept for next time. Faded for a `.tar`, which has none, and a `.tar.zst`, whose pure-Rust encoder has the one
  - 📚 **One archive for each** - of what is chosen, named after it, the name becoming `*.zip` and Tab still going through the formats; two that would have one name are numbered
  - 🗑️ **Then delete what went in** - for good, once the archive is there: only what is as it was packed, so a file changed meanwhile, one that could not be read, and a directory still holding something stay
  - 🚫 **Leave out** - patterns separated by `;`, as `tar --exclude` takes them: `.git` and `*.o` a file or a directory, `target/` a directory alone, and one with a `/` in it, as `src/*.rs`, found anywhere in a path. Kept for next time
  - 🔐 **Password**, typed twice, for a `.zip` or a `.7z` alone - see below

  Modes, times and links go in as they are; a zip or a 7z cannot hold a name that is not UTF-8, which is asked about, and a tar keeps it as it is. A 7z is packed solid, as 7-Zip packs one. Two of what is packed with one name - from a mixtape, or Find files - are asked about as a copy asks. It is written beside where it goes and put there whole, so a cancel leaves nothing, and an archive made inside the directory being packed leaves itself out. One already at the name is written over only when F11 says Overwrite, and never one of what is being packed
- 🔐 **Passwords** - a `.zip` packed with one has its files encrypted with AES-256, its names in the clear, as a zip has them; a `.7z` has its names encrypted too, as `7z -mhe=on` does. 7-Zip, WinZip and macOS read them; Info-ZIP's `unzip` does not read AES. An encrypted archive asks for its password as it is gone into, copied out of, extracted, viewed or written into - a 7z with its names locked before anything - and again when the one given is wrong. Given, it is kept while fm84 runs, never on disk, and an archive just packed with one opens with it. Written into, an encrypted archive takes what comes in under the same password, and a zip given the wrong one is left as it was
- 🔒 **Changed in place** - renaming inside an archive, F4, links and attributes still say "Archives are read-only" and leave it as it was: F3 shows a file instead of F4. A git commit opened as a folder is read-only throughout. Find files does not reach inside an archive yet
- 🛡️ **Safe to open** - a name that would land outside where it is copied to - `../`, an absolute path, a drive - never gets into the listing, nor anything that would be written through a link in the archive. An encrypted zip entry says so in the detail lines
- ♻️ **Kept up to date** - an archive written while a panel is in it is read again, climbing out of a directory it no longer has, and one deleted is left. A large `.tar.gz` is read once and kept, so going in and out of its directories does not unpack it again
- 💬 **Not an archive after all** - a file named like one that will not read says why, and the panel stays where it was
- 🕰️ **Git commits too** - Alt+G, R opens a branch, a tag, a stash or a commit as a folder that works the same way - see Navigation

## 📂 Directory Sizes
- 📏 **Calculated on select** - press Space on a directory to calculate its size; a link to one is selected but not counted, for the same reason as below
- 🗂️ **Every directory at once** - `Alt+Shift+Enter`, as in Total Commander (`Alt+Enter` too, for a terminal that cannot report Shift with Enter), sizes every directory in the panel, top to bottom, four at a time; the rest show `…` while they wait their turn. Links to directories are left out, since one to `/` or to a slow mount would walk all of it
- 🗺️ **Space map** - Alt+Shift+Enter also puts a bar behind each row, from the left, as long against the largest entry as the entry is, as ncdu draws it; the bars grow as directories are counted. The cursor's row keeps the cursor's colour, and the lines under the panels give its share instead, as `42% of 12 GiB`. The map stays with the directory it was asked for in - gone when the panel goes elsewhere, back when it returns
- 🔗 **Counted as du counts** - a file with several hard links counts once, and filesystems the kernel makes up - `/proc`, `/sys` and their kin - count nothing, so sizing `/` gives what is on the disk rather than the size of all memory
- 🧵 **Counted in the background** - the Size column shows the running total with a `…` while it counts, the panels keep answering, and Esc stops it, as does leaving the directory (unless the other panel is in it too); a slow disk or a huge tree no longer holds up the interface
- 📌 **Persistent display** - sizes stay visible after deselecting, until a copy, move or delete may have changed them


## ⌨️ Command line
- 📂 **Directories given** - take the place of the tab that would have shown; the panel's other tabs stay. A directory that does not exist is reported in the shell before anything starts. `--` ends the options, for a directory whose name starts with a dash
- 🐞 **Debug builds** - compile dependencies optimised too, so a plain `cargo run` still decodes images at full speed. The first debug build takes a little longer for it

## 📍 cd84 - leave the shell where fm84 was left
A program cannot change its shell's directory, so quitting fm84 normally drops you back where you started. `cd84` is a shell function that fixes that: it runs fm84, and on quitting goes to the directory of the active panel. Arguments pass through (`cd84 ~/Music`), and so does fm84's exit status. fm84 prints the function itself, so it always matches the binary it came with - `cargo install` users get it too.

It works for any directory name, a trailing newline or bytes that are not UTF-8 included, and stays put if fm84 did not quit normally - or quit with **Shift+F10**, for the times you only wanted a look around. Underneath, `--choosedir FILE` has fm84 write the directory to `FILE` on quitting, for any other wrapper that wants it.
